# PDF files for sharing from iPhone

The user still could not obtain report PDF files to attach in ChatGPT. A production check of an old `/app/static/reports/public_report_<token>.pdf` returned404 after a deployment. Opening the durable `/?public_report_token=...` report in an actual browser hydrated the temporary preview again: the PDF then returned200/application/pdf, with no Content-Disposition attachment header. The public landing page had a JavaScript Web Share control and a static download anchor, but no native file download control. Copying a report URL is not obtaining a PDF file attachment.

The report landing now provides a prominent native Streamlit `Last ned PDF-fil` control backed by the already validated durable report bytes and original stored filename, with MIME application/pdf. `on_click='ignore'` keeps the report page/session in place. Existing preview, sharing and return actions remain available. Brief iPhone guidance explains saving to Files and selecting the file as an attachment. No new endpoint or subscription is required.

Two browser regressions were observed failing before the change, then passing. At390 and1280 viewport widths they block every static-report request, download an actual PDF file, verify exact bytes by SHA256, read its PDF contents, check its filename, and verify unchanged page URL and report heading. These are Chromium mobile-width/desktop tests, not proof of physical iPhone Safari or ChatGPT attachment-picker behavior. Temporary synthetic previews are cleaned after the tests.

59 focused tests passed. The full local suite passed2767 tests, skipped270 and passed4 subtests; the same four local baseline failures remain: test_production_roots_and_complete_lock_are_exact_and_installed (installed pins), test_scheduler_blocks_huge_legacy_monolith_before_payload_fetch (old FakeCursor), test_packaged_universe_is_nonempty_but_not_claimed_as_exchange_master (universe fixture), test_new_breach_sends_pushover_after_configuration_change (time-sensitive FX alert). No checks are relaxed. One independent review found no Critical/Important findings; its optional stronger navigation assertion was incorporated before CI.

After rollout, use the durable report page, download the actual production PDF and compare it with stored PDF metadata. This change does not make copied transient static preview URLs permanent. The user flow is report page -> Last ned PDF-fil -> Save to Files -> attach the saved PDF in ChatGPT.
